# 離線覆核收件匣

1. 把確認後的覆核檔另存為 `原檔名_已確認.xlsx`（例如 `review_batch1_500_已確認.xlsx`）。
2. 用 GitHub 網頁上傳到本資料夾 `review_inbox/`（手機也可）。
3. 「離線覆核匯入」流程會自動執行，不呼叫 LLM、不使用 Groq 額度。
4. 完成後原檔移到 `review_inbox/done/`，並產生 `原檔名_已確認_結果.csv`（每一列的結果與略過原因）。

只有檔名結尾為 `_已確認.xlsx` 的檔案會被處理。

## 寫回的欄位

| 決定 | 寫入 |
| --- | --- |
| 維持 | 分類不變，只標記人工覆核 |
| 修改 | Event_Code、事件中文、Level、Action 依 `Parameter_Event.xlsx` 帶入 |
| 排除 | NOT_RELEVANT／無關新聞事件／Level 0／Action「排除、不納入風險事件」 |

所有列都會寫入：已人工覆核=True、需要人工覆核=False、分類狀態=人工覆核、最終判斷來源=人工覆核、人工版本（新隨機碼）、人工覆核人、人工覆核時間、人工修改欄位、覆核註記。
有填「更正公司」「更正Ticker」時一併更新 Company、Ticker。

## 會略過的列（不覆蓋）

- 人工版本與目前資料不一致（已被別人覆核，或同一檔重複匯入）。
- 目前事件代碼或 Level 與覆核檔不同（覆核檔產生後排程重判或被修改過），需重新產生覆核檔。
- 最終決定不是 維持／修改／排除，或「修改」沒有填合法的新事件代碼。
- 找不到該 news_id。

手動檢查可到 Actions →「離線覆核匯入」→ Run workflow，勾選 dry_run 只看結果不寫入。
